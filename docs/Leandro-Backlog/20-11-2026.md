### Passo 5: `app-alert`

- `shared/alert/alert.{ts,html,css,spec.ts}`:
  - `input()` para `type`, `message` (obrigatório) e `dismissible`;
  - `output()` `closed`, porque quem esconde o alerta é o pai, que é quem guarda a mensagem;
  - `@if` para mostrar o X.
- Variantes `success`, `error` e `warning`: cada uma só define 2 variáveis CSS locais.
- Acessibilidade: `role="alert"` nos erros e `role="status"` no resto; o X tem `aria-label`.
- `styles.css`: tokens `--color-success`, `--color-success-bg`, `--color-warning` e `--color-warning-bg` (PROVISÓRIOS).

### Passo 6: Login e Registo com a API real

- Decisão: a autenticação já funciona na API, por isso passou logo para `HttpClient` em vez de mock. Carros e reservas continuam com mock.
- `app.config.ts`: `provideHttpClient()`.
- `AuthService`: `login()` e `register()` devolvem `Observable<UserResponse>`. O `tap` guarda a sessão só no sucesso, e o `saveUser()` passou a privado.
- `core/http-error.ts`: **`getErrorMessage()`, escrito pelo Leandro**. Trata os 4 casos medidos na API:
  - `status 0` (API desligada);
  - texto simples;
  - ProblemDetails com `detail`;
  - 500 sem `detail`.
- Páginas `login` e `register`: `ngModel`, validação no browser (`required`, `email`, `minlength="6"`), erros por campo e alerta com a mensagem da API. O botão fica desativado durante o pedido.
- Depois do registo a pessoa entra logo e vai para `/cars`, porque a API devolve o mesmo `UserResponse`.
- `styles.css`, secção 6: layout `.auth`, partilhado pelas duas páginas.

### Erros encontrados na revisão (23/11) e corrigidos pelo Leandro

| Erro | Causa | Como foi apanhado |
| --- | --- | --- |
| `\|\|` em vez de `&&` no `getErrorMessage` | Com `\|\|`, um objeto (ProblemDetails) chegava ao `.trim()` e dava `TypeError` | 2 testes falharam |

| `template: './login.html'` em vez de `templateUrl` | `template` aceita HTML direto, por isso mostrava o texto `./login.html` no ecrã | Nem o build nem os testes: só o browser (e a string no bundle) |

## Decisões

| Decisão | Porquê |
| --- | --- |
| Autenticação já com `HttpClient`, o resto com mock | A autenticação está pronta na API; carros e reservas ainda não |
