## Decisões

| Decisão | Porquê |
| --- | --- |
| Datas validadas no ecrã com as mesmas mensagens da API | O utilizador vê o erro antes de reservar; a API valida na mesma, porque o browser pode ser contornado |
| Mock sem as regras R1 a R5 e C1 a C3 | As regras ficam num só sítio (API). Os erros 409/403 só se testam com a API real |
| Uma janela genérica (`app-confirm-modal`) | Reutilizada na reserva e no cancelamento |
| `<dialog>` nativo | Acessibilidade (foco, Esc, fundo) sem pacote nenhum |
| Erro da reserva fica dentro da janela | O utilizador ainda está a decidir; não perde o contexto |
| Datas com `date: 'dd/MM/yyyy' : 'UTC'` | "yyyy-MM-dd" é lido como meia-noite UTC; sem isto, um fuso atrás de UTC mostrava o dia anterior |
| Botão Cancelar não esconde pela data (C3) | A regra C3 é da API; repeti-la no ecrã punha-a em dois sítios |
